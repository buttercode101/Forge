# Phase 3 developer-preview brief

## Release boundary
Developer preview only. Do not market as a finished verification platform yet.

## Positioning
Your coding agent said “done.” Forge asks: what actually ran, against which commit, and what evidence supports completion?

## ICP
Serious Claude Code/Codex/Cursor/agent users running multi-step software changes who have already experienced premature completion or stale project state.

## Activation
forge scan -> one useful project-state observation -> forge verify rejects or proves a concrete claim.

## North star
Projects where Forge verifies or rejects a consequential completion claim using resolvable evidence.

## Monetization
Open-source core first. No paywall until repeated use is observed. Later candidate value: team history, shared policies, CI evidence retention.

## Experiments
1. Publish reproducible “agent says done / evidence says unverified” case. Success: developers run the same check locally. 14 days.
2. GitHub README install/scan/verify path. Success: external clone/install plus completed scan. 21 days.
3. Ask agent-heavy developers for one real false-completion transcript/evidence set. Success: 5 usable cases. 30 days.

## Launch copy
**One line:** Forge makes “done” answerable with evidence, not an agent summary.
